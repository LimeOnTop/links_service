## Сервис проверки ссылок

 Go-приложение предназначено принимать пачки URL, присваивать им идентификаторы, проверять доступность ресурсов и формировать PDF-отчёты по запросу.

### Основные возможности
- Принимать запросы `POST /api/v1/links/check`, сохранять список ссылок, возвращать статусы (`available` / `not available`) и номер набора (`links_num` / `links_sum`).
- Принимать запросы `POST /api/v1/links/report`, собирать данные по указанным `links_list` и отдавать PDF-отчёт.
- Хранить состояние на диске (`data/links_store.json`), переживать перезапуски и восстанавливать незавершённые задания.
- Выполнять graceful shutdown, дожидаться завершения активных запросов и корректно останавливать фоновые операции.
- Предоставлять health-check по `GET /healthz`.

### Запуск без контейнеров
```bash
go run ./cmd/server
```

### Запуск с контейнером
```bash
docker compose up -d
```


### API

**Проверить ссылки**
```http
POST /api/v1/links/check
Content-Type: application/json

{
  "links": ["google.com", "https://example.org"]
}
```

**Получить отчёт**
```http
POST /api/v1/links/report
Content-Type: application/json

{
  "links_list": [1, 2]
}
```

Ответ — PDF-файл с итоговыми статусами.

### Архитектура
- **Entity (`internal/entity`)** — Здесь описаны сущности и доменные ошибки.
- **Use case (`internal/usecase`)** — Инкапсулированы сценарии: проверка ссылок, формирование отчётов, восстановление задания.
- **Service (`internal/service`)** — адаптация внешних интерфейсов (HTTP API, проверку доступности, генерацию PDF).
- **Repository (`internal/repository`)** — обеспечение персистентности (файловое хранилище).
- **App (`internal/app`)** — сбор зависимостей и управление жизненным циклом; `cmd/server` только парсинг конфигурации и запуск `app.Run`.

### Надёжность и хранение
- Запись запросов в состоянии `pending` до завершения сетевой проверки.
- Сохранение исходных ссылок, меток времени и статусов.
- При перезапуске находятся незавершённые записи и завершаются их повторной проверкой.
- Использование `http.Server.Shutdown`, для корректного завершения активных запросов.

### Контейнеризация
- `Dockerfile`, чтобы собирать бинарь и запускать сервис в контейнере.
- `docker-compose.yml`, чтобы поднимать сервис с монтированием каталога `data/`.
- `Makefile`, чтобы автоматизировать сборку, запуск и остановку контейнеров.

### Работа с контейнерами
- `make docker-build`, чтобы собрать Docker-образ.
- `make compose-up`, чтобы поднять сервис в фоне (порт `8080`, том `./data`).
- `make compose-logs`, чтобы смотреть логи запущенного контейнера.
- `make compose-down`, чтобы остановить сервис.
- `make clean`, чтобы остановить сервис и удалить связанные тома.

### Ограничения
- Проверка доступности через HTTP(S); недоступные протоколы отмечаются как `not available`.
- Генерация PDF с помощью [`gofpdf`](https://github.com/jung-kurt/gofpdf) без внешних сервисов.
- Контроль рост файла `data/links_store.json`, архивация или чистка его при необходимости.
