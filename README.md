## Сервис проверки ссылок

 Go-приложение предназначено принимать пачки URL, присваивать им идентификаторы, проверять доступность ресурсов и формировать PDF-отчёты по запросу.

### Основные возможности
- Принимать запросы `POST /api/v1/links/check`, сохранять список ссылок, возвращать статусы (`available` / `not available`) и номер набора (`links_num` / `links_sum`).
- Принимать запросы `POST /api/v1/links/report`, собирать данные по указанным `links_list` и отдавать PDF-отчёт.
- Хранить состояние на диске (`data/links_store.json`), переживать перезапуски и восстанавливать незавершённые задания.
- Выполнять graceful shutdown, дожидаться завершения активных запросов и корректно останавливать фоновые операции.
- Предоставлять health-check по `GET /healthz`.

### Запуск без контейнеров
```bash
go run ./cmd/server
```

Параметры запуска:
- `PORT` или `-addr` — задавать адрес прослушивания (`:8080` по умолчанию).
- `-storage` — указывать файл хранилища (по умолчанию `data/links_store.json`).
- `-timeout` — задавать таймаут проверки одной ссылки (по умолчанию `5s`).
- `-workers` — задавать количество параллельных проверок (по умолчанию `5`).

Файл из `-storage` создавать самостоятельно либо предоставить права на запись директории `data/`.

### API

**Проверять ссылки**
```http
POST /api/v1/links/check
Content-Type: application/json

{
  "links": ["google.com", "https://example.org"]
}
```

**Получать отчёт**
```http
POST /api/v1/links/report
Content-Type: application/json

{
  "links_list": [1, 2]
}
```

Ответ — PDF-файл с итоговыми статусами.

### Архитектура
- **Entity (`internal/entity`)** — описывать сущности и доменные ошибки.
- **Use case (`internal/usecase`)** — инкапсулировать сценарии: проверять ссылки, формировать отчёты, восстанавливать задания.
- **Service (`internal/service`)** — адаптировать внешние интерфейсы (HTTP API, проверку доступности, генерацию PDF).
- **Repository (`internal/repository`)** — обеспечивать персистентность (файловое хранилище).
- **App (`internal/app`)** — собирать зависимости и управлять жизненным циклом; `cmd/server` только парсить конфигурацию и запускать `app.Run`.

### Надёжность и хранение
- Записывать запросы в состоянии `pending` до завершения сетевой проверки.
- Сохранять исходные ссылки, метки времени и статусы.
- При перезапуске находить незавершённые записи и завершать их повторной проверкой.
- Использовать `http.Server.Shutdown`, чтобы корректно завершать активные запросы.

### Контейнеризация
- Использовать `Dockerfile`, чтобы собирать бинарь и запускать сервис в контейнере.
- Использовать `docker-compose.yml`, чтобы поднимать сервис с монтированием каталога `data/`.
- Использовать `Makefile`, чтобы автоматизировать сборку, запуск и остановку контейнеров.

### Работа с контейнерами
- Выполнить `make docker-build`, чтобы собрать Docker-образ.
- Выполнить `make compose-up`, чтобы поднять сервис в фоне (порт `8080`, том `./data`).
- Выполнить `make compose-logs`, чтобы смотреть логи запущенного контейнера.
- Выполнить `make compose-down`, чтобы остановить сервис.
- Выполнить `make clean`, чтобы остановить сервис и удалить связанные тома.

### Ограничения
- Проверять доступность через HTTP(S); недоступные протоколы отмечать как `not available`.
- Генерировать PDF с помощью [`gofpdf`](https://github.com/jung-kurt/gofpdf) без внешних сервисов.
- Контролировать рост файла `data/links_store.json`, архивировать либо чистить его при необходимости.
